## Отступы (spacing)
- Шкала отступов проекта: `4, 8, 16, 24, 32, 40, 48px` и далее с тем же шагом (Tailwind default spacing scale) — используется для всех отступов/gap'ов на любых экранах. **Правило одно на все брейкпоинты**: при вёрстке адаптива (мобилка/планшет) значения по этой же шкале, отдельной "мобильной" шкалы нет — просто на маленьких экранах берём меньшие шаги той же шкалы (например `p-4`→`p-6` на десктопе может стать `p-4` на мобилке), но не произвольные пиксели вне шкалы.
- Внешний отступ секции от края экрана: `16px` (`p-4`) — паттерн: полноширинная секция с `padding: 16px`, внутри неё скруглённая (`rounded-[40px]`) карточка на всю оставшуюся ширину/высоту
  - **⚠️ Full-bleed секции на очень широких экранах (2026-08-24)** — паттерн выше (`w-full p-4`, без ограничения максимальной ширины) на экранах шире дизайн-макета (напр. большой телевизор/ультраширокий монитор) визуально "прилипает" к краям: `16px` отступ теряется на фоне огромной ширины экрана. Пользователь заметил на `Hero.tsx` и `PrivateTour.tsx` (проверял с экрана телевизора). Фикс — добавить `mx-auto max-w-[1920px]` к секции (`mx-auto w-full max-w-[1920px] p-4`), тогда на экранах шире 1920px по бокам появляются нормальные симметричные поля вместо растягивания на всю ширину. Применено пока только к `Hero.tsx` и `PrivateTour.tsx` (по явному запросу — "для начала эти два"). ⚠️ **`Header.tsx` (`inset-x-4`, `position: fixed`) и `Footer.tsx` (та же full-bleed inset-карточка, см. ниже) используют тот же паттерн без ограничения ширины — вероятно, тот же баг, но пока не тронуты, ждут отдельного захода.**
- Внутренний отступ навбара от края карточки: `40px`
- Вертикальный ритм контент-блока hero (гео → заголовок → текст → кнопка): `~24px` (`gap-6`)

## Радиусы / тени
- Border-radius карточки/секции: `40px`
- Border-radius кнопок и пилюль (geo-плашка, CTA): `9999px` (`rounded-full`)
- Тени: не обнаружены в собранных блоках пока

## Адаптив (responsive)
- **Начали 2026-08-24, с Hero, с мобилки вертикальной.** Брейкпоинты по плану (согласовано с пользователем): мобилка портрет (390) → мобилка ландшафт (844) → планшет портрет (768) → планшет landscape/больше (1024). ⚠️ Обратите внимание: мобилка-ландшафт (844) ШИРЕ, чем планшет-портрет (768) — это не строго возрастающая по ширине последовательность, брейкпоинты по типу устройства, не только по ширине. Пока (только Hero) используется дефолтный Tailwind `md:` (768px) как единственная граница: без префикса = мобилка портрет (база), `md:` = десктоп (текущий, ~1440 baseline). Когда дойдём до ландшафт-моб/планшетов отдельно, вероятно понадобятся кастомные брейкпоинты через `--breakpoint-*` в `@theme` (`globals.css`), т.к. 844 не укладывается чисто в дефолтную шкалу Tailwind между `md`(768) и `lg`(1024).
- **Hero.tsx на мобилке** — референс от пользователя (скриншот стороннего сайta "Ветерок") как ориентир, не точный спек: полноэкранный full-bleed фон, без скруглений. Реализовано: секция `p-0 md:p-4` (без внешнего отступа на мобилке), карточка `h-dvh rounded-none md:h-[750px] md:rounded-[40px]` (`h-dvh`, а не `h-screen` — корректно учитывает схлопывание адресной строки в мобильных браузерах, `h-screen`/100vh даёт скачки лейаута). Кнопка "View tours" — высота `h-[50px]` НЕ меняется на мобилке (явное требование пользователя), текст/паддинг кнопки тоже оставлены как на десктопе. Внешний отступ nav (`inset-x-10 top-10` → `inset-x-4 top-4` на мобилке) уменьшен, но сам `NavbarContent.tsx` не трогали.
  - **⚠️ Фиксированный px для заголовка ломался на разных телефонах (пофикшено 2026-08-25)** — изначально `text-[40px]` для h1 подбирался на глаз под 390px (iPhone 12/13/14) и там смотрелся чисто, но на 430px (iPhone 14/15 Pro Max) внутренний перенос "wild side" переставал влезать в одну строку и разваливался на 3 строки вместо 2 (форсированный `<br/>` перед "of Kazakhstan" рассчитан на "Discover the wild side" в один ряд). **Фикс — `clamp()` вместо фиксированного px**: `text-[clamp(28px,8.5vw,44px)]` для h1, `text-[clamp(13px,3.6vw,18px)]` для параграфа-подзаголовка — размер плавно масштабируется от ширины экрана, без резких переломов на конкретных модельных ширинах. Проверено вручную на 360/390/414/430px (iPhone SE → iPhone Pro Max) — везде по 2 чистые строки, без переполнения. **Паттерн для будущего**: на мобильных заголовках/тексте, где включён форсированный `<br/>` под конкретную раскладку слов, использовать `clamp()`, а не фиксированный px — телефоны сильно отличаются по ширине (360–430px) и один статичный размер почти гарантированно ломается на части диапазона.
  - **⚠️ Devtools-заметка**: во время проверки на 430px через `chrome-devtools-mcp` `take_screenshot` несколько раз отдавал скриншот с "обрезанным" контентом (пропадала кнопка-бургер, текст обрывался на правом краю), хотя JS-замеры (`getBoundingClientRect`) на той же странице однозначно показывали, что переполнения нет и всё влезает. Оказалось — глюк самого инструмента скриншотов после нескольких emulate/reload подряд на одной вкладке (лечится открытием свежей вкладки). Если при проверке адаптива скриншот выглядит сломанным, но JS-замеры чистые — сначала пересоздать вкладку, не чинить код вслепую по скриншоту.
  - **`NavbarContent.tsx` мобильная раскладка (2026-08-24, отдельный заход)** — на мобилке (`md:hidden`) теперь только лого слева + круглая кнопка-гамбургер справа (`size-11 rounded-full`, фон `bg-white/16 backdrop-blur-[3.5px]` для light-темы / `bg-ink/10` для dark, иконка — новый `MenuIcon.tsx`, 3 горизонтальные линии `currentColor`, тот же паттерн что `GlobeIcon.tsx`). Десктопная раскладка (лого + инлайн-меню + language switcher + телефон) не тронута, просто обёрнута в `hidden md:grid` вместо старого голого `grid`. Автоматически подхватилось и в sticky `Header.tsx` (общий компонент). Кнопка открывает мобильное меню (drawer) — см. раздел "Мобильное меню" ниже (реализовано 2026-08-25).
- **Правило шрифтов для мобилки (зафиксировано 2026-08-25, применять во всех следующих блоках)** — вместо фиксированного `text-[Npx]` на мобильной базе использовать `text-[clamp(min,Xvw,max)]`, десктопное значение как было через `md:text-[Npx]`. Причина — телефоны сильно отличаются по ширине (360–430px), один статичный px почти гарантированно ломает перенос строк на части диапазона (см. баг с Hero h1 выше). Ориентировочная формула: `min ≈ desktop×0.35`, `max ≈ desktop×0.5`, `vw ≈ 8.5 × (desktop / 80)` (выведено из рабочего значения Hero h1 80px→`clamp(28px,8.5vw,44px)`) — не догма, подгонять на глаз и проверять на 360/390/414/430px, но сам факт использования `clamp()` вместо фикс. px — обязателен для любого мобильного текста, где есть перенос строк.
- **Features.tsx на мобилке (2026-08-25)** — референс от пользователя (скриншот стороннего сайта) использован ТОЛЬКО как идея раскладки (сетка 2×2), не цвета/шрифты/контент. `grid-cols-2 gap-4 md:grid-cols-4 md:gap-6`, карточка `h-[180px] rounded-[20px] p-3 md:h-[300px] md:rounded-[30px] md:p-4`, текст карточки `text-[clamp(15px,4vw,18px)] md:text-[32px]`, заголовок блока `text-[clamp(24px,6.5vw,32px)] md:text-[60px]` (по правилу шрифтов выше). Отступы секции тоже уменьшены на мобилке: `py-12 md:py-20`, `mt-8 md:mt-16` между заголовком и сеткой. Проверено на 360/390/430px и десктопе — всё чисто, 4-в-ряд на десктопе не тронут.
- **Tours.tsx на мобилке (2026-08-25)** — референс от пользователя снова только как идея раскладки (2 карточки в ряд). `grid-cols-2 gap-4 md:grid-cols-3 md:gap-6` — т.к. это обычная CSS grid, любое количество туров в `data/tours.ts` само распределится по 2 в ряд, следующий ряд начнётся автоматически, ничего доп. настраивать не нужно при добавлении новых туров. Секция `py-12 md:py-20`, `mt-8 md:mt-16`, заголовок `text-[clamp(24px,6.5vw,32px)] md:text-[60px]` (тот же паттерн, что в Features — переиспользуем формулу шрифта между блоками с одинаковым десктопным h2 в 60px). Карточка тура (`TourCard.tsx`) на мобилке: заголовок `text-[15px] min-h-[40px]` (было `text-2xl min-h-[60px]`), цена-пилюля `h-[36px] text-sm px-3` (было `h-[50px] text-2xl px-5`), кнопки `h-[40px] text-sm` без `max-w` кэпа (было `h-[50px] text-[22px] max-w-[220px]` — на мобилке кнопка тянется на всю ширину карточки, кэп возвращается на `md:`). Галерея (`TourGallery.tsx`): фото `h-[160px] rounded-[16px]` (было `h-[350px] rounded-[30px]`), бейдж/стрелки-навигации/точки тоже пропорционально уменьшены. Проверено на 360/390/430px и десктопе (1440) — 3-в-ряд на десктопе не тронут.
- **PrivateTour.tsx на мобилке (2026-08-25)** — просто, без референса. Основная проблема была не в размерах текста, а в `px-16` (64px с каждой стороны) — на мобилке это съедало почти всю ширину карточки. Фикс: `px-6 md:px-16`. Высота была фиксированная `h-[569px]` — заменена на `py-12 md:h-[569px] md:py-0` (auto-height по контенту на мобилке, фикс. высота остаётся только на десктопе, чтобы контент не обрезался при любой комбинации текста). Заголовок/подзаголовок — `clamp()` по правилу: `text-[clamp(24px,6.5vw,32px)] md:text-[60px]` (тот же h2, что в Features/Tours) и `text-[clamp(17px,4.8vw,24px)] md:text-[32px]` для параграфа. Центрирование (`items-center`, `text-center`) уже было в коде, трогать не пришлось — форма (`PrivateTourForm.tsx`, инпуты `h-[50px] text-[20px]`) не потребовала изменений, на 360px влезает нормально как есть. Проверено на 360/390/430px и десктопе — не сломано.
- **Reviews.tsx на мобилке (2026-08-25)** — без референса, просто "чтобы читаемо и влезало". Карточка отзыва (`ReviewCard.tsx`) уменьшена `w-[411px] h-[240px]` → `w-[300px] h-[180px]` (`md:` — старые значения), внутренние отступы/шрифты пропорционально уменьшены: аватар `size-8` (было `size-10`), имя `text-sm` (было `text-[20px]`), дата `text-xs` (было `text-base`), текст отзыва `text-xs line-clamp-4` (было `text-base line-clamp-5`), паддинг карточки `p-3` (было `p-4`). Marquee-анимация (`animate-marquee-left/right`, бесконечная лента) не тронута — работает с любым размером карточки одинаково, т.к. трек это просто `flex` с двойным набором данных. Проверено на 360/390/430px и десктопе — карточки читаемые, влезают по 1.2-1.5 на экран с fade-краями, десктопный размер не тронут.

Клик по невидимой (пока не проскроллено) кнопке Header'а открывал портал-drawer, но видимая кнопка в Hero не знала об этом и продолжала показывать иконку гамбургера — рассинхрон. **Фикс**: состояние вынесено в `MobileMenuProvider` (React Context, тот же принцип, что уже был у `LanguageProvider` для языка) — оба триггера теперь читают/пишут один и тот же `isOpen`.
  - **⚠️ Баг №2 (пофикшено): drawer тоже рендерился дважды** — раньше JSX самого drawer лежал прямо в `NavbarContent.tsx`, значит с двумя монтированиями получались два одинаковых drawer'а в DOM (задваивались кнопки/ссылки/aria). **Фикс**: JSX drawer'а вынесен в отдельный `MobileMenu.tsx`, который `page.tsx` рендерит один раз — `NavbarContent.tsx` теперь содержит только кнопку-триггер (лого + круглая кнопка, иконка переключается hamburger↔крестик по `isOpen` из контекста).
  - **⚠️ Баг №3 (пофикшено): `z-45` не существует в Tailwind** — дефолтная z-index шкала это `0/10/20/30/40/50`, `z-45` — не валидный класс (тихо игнорируется, без CSS). Использовать `z-[45]` (квадратные скобки) для нестандартных значений.
  - **⚠️ Баг №4 (пофикшено): z-index терялся из-за вложенных stacking context** — `<header>` (`Header.tsx`) уже имел собственный `z-50`, что создаёт новый stacking context; любой z-index у дочерних элементов (даже `z-[60]`) не может "пробить" потолок родителя относительно внешних элементов. Портал `MobileMenu` рендерится в `document.body`, минуя вложенность Hero/Header, но чтобы кнопка-триггер (крестик) оставалась КЛИКАБЕЛЬНОЙ И ВИДИМОЙ поверх drawer'а — `Header.tsx` пришлось поднять с `z-50` до `z-[70]` (drawer `z-[58]`, backdrop `z-[55]`, запас между всеми слоями). **Паттерн на будущее**: если что-то с высоким z-index не показывается поверх портала — проверить, не капает ли его СОБСТВЕННЫЙ z-index у ближайшего позиционированного предка с уже заданным (не `auto`) z-index.
  - **Структура drawer'а**: справа, `fixed inset-y-0 right-0 w-[82%] max-w-[340px]`, `translate-x-full` → `translate-x-0` при открытии (`transition-transform duration-300`), фон `bg-ink/90 backdrop-blur-md`, без скруглений (edge-to-edge по референсу, не капсула). Контент сверху вниз: лого → `LanguageSwitcher` (theme="light") → ссылки меню (`text-xl`, `gap-5`) → WhatsApp-иконка + телефон → кнопка "Write on WhatsApp" (`mt-auto`, прижата к низу). Backdrop — `fixed inset-0 bg-black/60 backdrop-blur-sm`, клик по нему закрывает меню. `document.body.style.overflow = "hidden"` пока меню открыто (блокировка скролла фона), снимается в cleanup эффекта. Портал монтируется только после `useEffect` (`mounted` state) — избегаем SSR-мисматча, т.к. `document.body` не существует на сервере.

- **Fade-градиент по краям (marquee-fade)** — класс `.marquee-fade` в `globals.css`, `mask-image`/`-webkit-mask-image: linear-gradient(to right, transparent, black 10%, black 90%, transparent)` на контейнере с `overflow-hidden`. - **Композитинг ассетов из отдельных PNG на прозрачном холсте** — паттерн для карточек без готового Figma-канваса: `ffmpeg -f lavfi -i "color=c=black@0.0:s=WxH:r=1,format=rgba" -i asset1.png -i asset2.png -filter_complex "[1:v]format=rgba,scale=...,rotate=...:c=none:ow=rotw(...):oh=roth(...)[a];[2:v]format=rgba,scale=...[b];[0:v][a]overlay=x:y[tmp];[tmp][b]overlay=x:y" -frames:v 1 -pix_fmt rgba out.png`. Важно: явно указывать `format=rgba` на КАЖДОМ шаге (source, каждый input, каждый overlay) — иначе альфа-канал молча теряется и прозрачный фон становится непрозрачным чёрным (наступали на этот баг). Проверять прозрачность перед конвертацией в WebP: `ffmpeg -i out.png -vf "crop=4:4:x:y,format=rgba" -f rawvideo - | xxd` — последний байт каждого пикселя должен быть `00` в прозрачных зонах.

## Технические заметки
- **Лимит Figma MCP (Starter, 20 запросов/месяц)** — исчерпан 2026-08-23 на блоке Footer. `get_metadata` в моменте ещё работал, `get_design_context`/`get_screenshot` — уже нет. Это НЕ дневной лимит, сбрасывается раз в месяц. Пока не сброшен (или план не проапгрейжен) — новые блоки собирать только по тому, что даёт `get_metadata` (координаты, текст, структура), либо по присланным вручную скринам/ассетам. Помечать такие блоки как "нужно сверить визуально" — см. Footer выше.
- **Next.js 16 (Turbopack, dev) — баг `/_next/image` при Accept: avif+webp**: рантайм-оптимизатор изображений зависает намертво (запрос никогда не резолвится), когда браузер шлёт стандартный `Accept: image/avif,image/webp,...`. Не воспроизводится через `curl` с простым Accept-заголовком — только в реальном браузере. Обходим через проп `unoptimized` на `next/image` для уже вручную оптимизированных ассетов (в `/public/features`). Если баг всплывёт на других картинках — тот же обход. Стоит перепроверить при апгрейде Next.js, возможно пофиксят.
