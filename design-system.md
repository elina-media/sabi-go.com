## Отступы (spacing)
- Внешний отступ секции от края экрана: `16px` (`p-4`) — паттерн: полноширинная секция с `padding: 16px`, внутри неё скруглённая (`rounded-[40px]`) карточка на всю оставшуюся ширину/высоту
- Внутренний отступ навбара от края карточки: `40px`
- Вертикальный ритм контент-блока hero (гео → заголовок → текст → кнопка): `~24px` (`gap-6`)

## Радиусы / тени
- Border-radius карточки/секции: `40px`
- Border-radius кнопок и пилюль (geo-плашка, CTA): `9999px` (`rounded-full`)
- Тени: не обнаружены в собранных блоках пока

## Компоненты (переиспользуемые паттерны)
- **CTA-кнопка** (`bg-accent`, `rounded-full`, белый текст, иконка слева, `h-[50px]`, `px-4`, `gap-2`) — см. `Hero.tsx`, кнопка "View tours". Переиспользовать для других CTA на сайте.
- **Стеклянная плашка (glass pill)** — `bg-white/16`, `backdrop-blur-[3.5px]`, `rounded-full` — использована для гео-метки, возможно пригодится для бейджей/тегов в других блоках.
- **Полноширинная секция с inset-карточкой** — `section` с `p-4`, внутри `div` с `rounded-[40px]` и `overflow-hidden` на всю доступную площадь. Паттерн для hero и потенциально других full-bleed блоков.
- **Видео-фон** — `<video autoPlay loop muted playsInline poster={...} className="object-cover">` вместо фото. Используется в hero. Видео обязательно готовить заранее: обрезать под нужный aspect ratio блока и сжимать (H.264, `-an`, `-movflags +faststart`, CRF ~26), иначе вес страницы взлетает.
- **Feature-карточка** (все 4 в Features) — картинка скомпонована под размер карточки (302×300 canvas, прозрачный низ под текст) и рендерится `fill object-cover` на всю карточку, текст поверх снизу (`relative`, карточка `relative`). Канвас для всех 4 карточек, включая 4-ю (guides.webp), теперь приходит готовым из Figma — пользователь убрал сертификат IELTS из дизайна 2026-08-23, проблема решена на уровне исходника.
- **Tour-карточка** (`Tours.tsx` + `TourCard.tsx` + `TourGallery.tsx` + `data/tours.ts`) — data-driven: контент карточек (заголовок, цена, массив фото, бейдж, ссылки) вынесен в массив `tours` в `src/data/tours.ts`, компонент карточки просто мапит данные. Карточка: фото `h-[350px] rounded-[30px] object-cover` (компактный размер, обновлено 2026-08-23 — раньше было 440/540px, не помещалось на экран) + бейдж-плашка (glass pill) в правом верхнем углу поверх фото, заголовок 24px, цена — отдельная плашка (`bg-muted rounded-full h-[50px] px-5`, не просто текст), две кнопки-пилюли по левому краю (`max-w-[302px]` без `mx-auto`): `bg-accent` "Book a tour" и `bg-ink` "More". Когда появятся реальные пакеты туров — просто редактировать/добавлять записи в `tours.ts` и класть картинки в `/public/tours/`, компоненты трогать не нужно.
- **Фиксированная высота заголовка для выравнивания низа карточки** — заголовок тура: `line-clamp-2 min-h-[60px]` (60px = 2 строки при `text-2xl leading-tight`). Так цена и кнопки всегда на одном уровне между карточками независимо от длины заголовка (1 или 2 строки) — проверено вручную с однострочным заголовком. Важно: это работает и в сетке, и в будущем мобильном слайдере (где карточки не могут "мериться" высотой друг с другом, в отличие от `align-items: stretch` в общем ряду) — сознательно выбран этот способ вместо grid-stretch именно из-за планов на мобильный слайдер туров. Паттерн переиспользовать для любых карточек с заголовком переменной длины, где высота должна быть предсказуемой вне зависимости от контекста (грид/слайдер/список).
- **Галерея фото в карточке (TourGallery.tsx)** — `"use client"` компонент, каждый тур в `tours.ts` хранит `images: {src, alt}[]` вместо одной картинки. Стрелки-кнопки (SVG-шеврон, `bg-white/80` пилюли по бокам) и точки-индикатор снизу показываются АВТОМАТИЧЕСКИ, только если `images.length > 1` — с одной картинкой (как сейчас у всех туров) стрелки скрыты, ничего лишнего на экране. Проверено вручную (клики Next/Previous, зацикливание в обе стороны) — работает. Когда появятся доп. фото тура — просто добавить объекты в массив `images` этого тура, компонент подхватит сам.
- **Аккордеон (FAQ.tsx + FaqItem.tsx + data/faq.ts)** — data-driven, состояние "какая карточка открыта" живёт в родителе `Faq.tsx` (`"use client"`, `useState<string | null>`), а не в каждой карточке — так гарантируется, что открыта максимум одна карточка сразу (открытие новой автоматически закрывает предыдущую). Плавная высота без фиксированных px и без JS-измерения — CSS grid-трюк: `grid-rows-[0fr]` → `grid-rows-[1fr]` с `transition-[grid-template-rows]`, внутри `overflow-hidden`. Иконка (декоративная "звёздочка" в белом круге, не буквальный `+`, — файл `/public/faq/plus.svg`) поворачивается на 45° при открытии через `rotate-45` + `transition-transform`. `aria-expanded` на кнопке для доступности. Проверено вручную кликами — открытие/закрытие и "только один открыт" работают. Важно: на grid-контейнере обязателен `items-start` — без него CSS Grid по умолчанию растягивает (`align-items: stretch`) все карточки в ряду по высоте самой высокой, и закрытый сосед открытой карточки визуально "распухает" пустым местом (наступали на этот баг). Ответы — Lorem Ipsum-заглушка (`LOREM` константа в `data/faq.ts`), вопросы — тот же плейсхолдер, что и в Figma; заменить реальным контентом при необходимости, компоненты трогать не нужно.
- **Общий стейт языка (LanguageProvider.tsx)** — React Context, оборачивает всё приложение в `layout.tsx` (`<body><LanguageProvider>{children}</LanguageProvider></body>`). `LanguageSwitcher.tsx` (используется и в Hero-navbar, и в sticky Header — два разных инстанса на странице одновременно) берёт `current`/`setCurrent` из `useLanguage()` вместо локального `useState` — поэтому выбор языка в одном месте сразу отражается в другом. Понадобилось, когда добавили sticky Header: до этого каждый `LanguageSwitcher` был независим.
- **Языковой переключатель (LanguageSwitcher.tsx)** — `"use client"`, живёт в hero navbar слева от WhatsApp-иконки/номера. Триггер: глобус (`/hero/global.svg`) + текущий код языка (по умолчанию "ENG") + шеврон (поворот 180° при открытии). Полный список языков `["ENG", "RU", "KZ", "العربية"]` хранится отдельно от `current`; дропдаун рендерит `allLanguages.filter(lang => lang !== current)` — то есть в списке всегда все языки КРОМЕ текущего. При выборе нового языка старый автоматически возвращается в список (просто перестаёт быть исключённым фильтром), а выбранный пропадает из списка (переехал в триггер). Это чисто UI-переключатель пока — сайт ещё не мультиязычный (см. статус проекта), реального i18n за этим не стоит, просто меняет отображаемый лейбл.
  - Открывается ОБОИМИ способами — наведением (`onMouseEnter`/`onMouseLeave` на обёртке) и кликом. Клик по кнопке — именно `setIsOpen(true)`, а НЕ toggle: при toggle реальное движение мыши сначала открывает через hover, а клик следом сразу переключает обратно на закрыто (пойманный и исправленный баг).
  - Закрытие по клику вне виджета — через `useRef` + `document.addEventListener("mousedown", ...)` в `useEffect` (для сенсорных экранов, где hover не работает).
  - **Важно про "мёртвую зону" при hover-дропдаунах**: между триггером и выпадающим списком НЕЛЬЗЯ оставлять внешний отступ (`margin`/`mt-*`) — так как `<ul>` вынесен `position: absolute`, он не входит в layout-высоту родительского `relative`-контейнера, и зазор между кнопкой и списком оказывается вне hoverable-зоны родителя. При движении мыши вниз курсор на миг покидает область наведения → React снимает `isOpen` → список размонтируется раньше, чем курсор до него доедет (ровно этот баг словили и почему список "пропадал" при попытке кликнуть по языку). Решение — убрать внешний отступ (`mt-0`, список примыкает вплотную к триггеру), а визуальный воздух делать внутренним паддингом самого списка (`pt-1` и т.п.), а не зазором снаружи. Паттерн переиспользовать для любых будущих hover-дропдаунов.
- **Плавная навигация по якорям** — `html { scroll-behavior: smooth; }` в `globals.css` (глобально для всех `<a href="#...">`). Пункты меню (`NavbarContent.tsx`, дублируются в footer `Footer.tsx`) — реальные ссылки на `id` секций: `#main` (Hero), `#tours` (Tours), `#private-tour` (PrivateTour), `#reviews` (Reviews), `#contacts` (Footer). На каждой из этих секций (кроме Hero, она и так в самом верху) — `scroll-mt-[140px]`, чтобы фиксированный sticky Header (100px + отступы) не перекрывал верх секции при переходе. ⚠️ При тестировании через автоматизацию браузера: `scroll-behavior: smooth` анимирует скролл ~300–500ms — если проверяешь `window.scrollY` сразу после клика/`scrollIntoView()`, получишь `0` (это не баг, просто анимация ещё не началась/не закончилась) — нужно подождать перед проверкой.
- **Общий контент navbar (NavbarContent.tsx)** — вынесен из `Hero.tsx`, переиспользуется в `Hero.tsx` (embedded, поверх видео) и `Header.tsx` (sticky, поверх капсулы). Принимает `theme?: "light" | "dark"` — управляет цветом текста/лого/иконки языка (`text-white`/`text-ink`, `/hero/logo.svg` vs `/hero/logo-dark.svg`). `LanguageSwitcher` и `GlobeIcon` тоже принимают `theme`/красятся через `currentColor`. Тёмный вариант лого — `/public/hero/logo-dark.svg`, сделан из белого через `sed 's/fill="white"/fill="#262626"/g'`.
- **Sticky Header (Header.tsx)** — `"use client"`, `position: fixed`, `inset-x-4 top-4` (та же ширина/отступ, что у full-bleed карточек в Hero/PrivateTour). Капсула: `h-[100px] rounded-[25px] bg-ink/40 backdrop-blur-md px-10` (итеративно поднимали непрозрачность по запросу пользователя 2026-08-23: 15% → 25% → 40%). Появление по скроллу — `window.scrollY > 700` (примерно высота Hero-секции), плавно через `transition-all` + `opacity`/`-translate-y-4`, и `pointer-events-none` пока скрыт (чтобы невидимый хедер не перехватывал клики). Порог 700 — хардкод, не измеряется динамически; если высота Hero изменится, подправить константу `SCROLL_THRESHOLD`.
  - **Контраст на капсуле — прошли через 3 итерации**: (1) белый фон 10% + белый текст — нечитаемо на белых секциях страницы; (2) белый фон 10% + тёмный текст — тоже не устроило пользователя; (3) финально — тёмная капсула `bg-ink/15` + белый текст, читается и на фото, и на белом фоне. Если понадобится похожий glass-компонент — начинать сразу с тёмной подложки + светлого текста, не с прозрачно-белой.
- **Форма (Private tour)** (`PrivateTour.tsx` + `PrivateTourForm.tsx`) — секция вынесена в серверный компонент (фон/заголовок/текст), сама форма — отдельный `"use client"` компонент (`PrivateTourForm.tsx`), т.к. нужен интерактивный state. Инпуты — белые пилюли `h-[60px] rounded-[70px]`, plaseholder = название поля (`opacity-50`), фокус — `focus:ring-2 focus:ring-accent`. На сабмит: HTML5-валидация (`required`, `type="tel"/"email"`), состояние `idle/submitting/success`, пока данные просто логируются в консоль (`console.log`) — реальную отправку (Telegram-бот/Google Sheets) подключить в `handleSubmit` внутри `PrivateTourForm.tsx`, там уже есть `TODO`-комментарий с местом для этого.
  - **Видео вместо фото-фона** (2026-08-24) — фон секции заменён со статичного `background.webp` на `<video>` (тот же паттерн, что в `Hero.tsx`: `autoPlay loop muted playsInline`, `absolute inset-0 size-full object-cover`, `poster` для первого кадра до загрузки). Исходник от пользователя — 4K60fps `~100MB`, наездники на лошадях на фоне гор. Постер — первый кадр сжатого видео, `/public/private-tour/background-poster.jpg`. Старый сложный оверлей (`bg-gradient-to-l from-white/60 to-black/60 mix-blend-multiply`) заменён на простой `bg-black/40` по явному запросу пользователя — так же, как в Hero. Старый `background.webp` удалён как неиспользуемый.
  - **Кадрирование видео — наездники по центру блока** (2026-08-24) — секция очень широкая и невысокая (`h-[569px]`, но во всю ширину страницы), а в исходном видео наездники были в нижней трети кадра → `object-cover` с дефолтным центрированием обрезал видео так, что они оказывались у самого низа блока (~85% вниз). Через `object-position` на CSS-уровне это НЕ решить полностью — под наездниками в исходном кадре было недостаточно "запаса" по вертикали (посчитано: максимум, чего добиться через `object-position: bottom`, — это ~65% вниз, не центр), так как это упирается в геометрию (высота видимого окна кадрирования при данном соотношении сторон блока фиксирована и центр окна физически не дотягивается до наездников. Решение — перекадрировали ИСХОДНИК через `ffmpeg` (`crop=3840:1170:0:990` от оригинала 4K, затем `scale=1280:390`) так, чтобы новое видео уже само по себе было широкоформатным (~3.28:1) и наездники были центрированы в нём по вертикали; за счёт того что это соотношение шире, чем у блока (~2.47:1 при 1440px-дизайне), `object-cover` теперь обрезает только по бокам (лево/право), а по вертикали видео вписывается без обрезки — наездники остаются по центру независимо от реальной ширины окна. **Паттерн для будущего**: если фоновое видео/фото показывает объект не по центру кадра, а блок очень широкий/невысокий — не пытаться подогнать через `object-position`, сразу проверить, хватает ли "запаса" вокруг объекта в исходнике для симметричного кропа; если нет — перекадрировать так, чтобы новое соотношение сторон источника было ЗАМЕТНО шире (не уже) соотношения сторон блока, тогда `object-cover` обрежет только горизонталь и вертикальное позиционирование станет "бесплатным" и стабильным на любой ширине экрана.
- **Бесконечная карусель (marquee)** (`Reviews.tsx` + `ReviewCard.tsx` + `Stars.tsx` + `data/reviews.ts`) — data-driven как Tours. Паттерн: контейнер `overflow-hidden`, внутри трек `flex w-max gap-6` с ДВУМЯ копиями массива данных подряд (`[...reviews, ...reviews]`), анимация `translateX(0) → translateX(-50%)` (или наоборот для противоположного направления) через CSS `@keyframes` в `globals.css` (`.animate-marquee-left` / `.animate-marquee-right`, `linear infinite`, сейчас **76.5s**, было 45s — замедлено ×1.7 по запросу пользователя 2026-08-24). За счёт двойного трека переход через -50% визуально бесшовный. Пауза при наведении — `group-hover:[animation-play-state:paused]`. Обязательно учитывать `prefers-reduced-motion: reduce` (отключать анимацию). Карточка отзыва — `bg-muted rounded-[30px] p-4`, фикс. размер `411×240`, `overflow-hidden` + фиксированный `gap-6` между шапкой и текстом (не `justify-between` — при длинном тексте это давало нестабильный отступ и переполнение), текст отзыва — `line-clamp-5`, чтобы не вылезал за пределы карточки при любой длине. Имя — `text-[20px]` (было `text-2xl`/24px, уменьшено по запросу пользователя 2026-08-24). Аватар `size-10 rounded-full`, звёзды — переиспользуемый `Stars.tsx` (принимает `rating`, рисует SVG-путь звезды `n` раз, красит `fill-accent`/серым).

- **Композитинг ассетов из отдельных PNG на прозрачном холсте** — паттерн для карточек без готового Figma-канваса: `ffmpeg -f lavfi -i "color=c=black@0.0:s=WxH:r=1,format=rgba" -i asset1.png -i asset2.png -filter_complex "[1:v]format=rgba,scale=...,rotate=...:c=none:ow=rotw(...):oh=roth(...)[a];[2:v]format=rgba,scale=...[b];[0:v][a]overlay=x:y[tmp];[tmp][b]overlay=x:y" -frames:v 1 -pix_fmt rgba out.png`. Важно: явно указывать `format=rgba` на КАЖДОМ шаге (source, каждый input, каждый overlay) — иначе альфа-канал молча теряется и прозрачный фон становится непрозрачным чёрным (наступали на этот баг). Проверять прозрачность перед конвертацией в WebP: `ffmpeg -i out.png -vf "crop=4:4:x:y,format=rgba" -f rawvideo - | xxd` — последний байт каждого пикселя должен быть `00` в прозрачных зонах.

## Технические заметки
- **Лимит Figma MCP (Starter, 20 запросов/месяц)** — исчерпан 2026-08-23 на блоке Footer. `get_metadata` в моменте ещё работал, `get_design_context`/`get_screenshot` — уже нет. Это НЕ дневной лимит, сбрасывается раз в месяц. Пока не сброшен (или план не проапгрейжен) — новые блоки собирать только по тому, что даёт `get_metadata` (координаты, текст, структура), либо по присланным вручную скринам/ассетам. Помечать такие блоки как "нужно сверить визуально" — см. Footer выше.
- **Next.js 16 (Turbopack, dev) — баг `/_next/image` при Accept: avif+webp**: рантайм-оптимизатор изображений зависает намертво (запрос никогда не резолвится), когда браузер шлёт стандартный `Accept: image/avif,image/webp,...`. Не воспроизводится через `curl` с простым Accept-заголовком — только в реальном браузере. Обходим через проп `unoptimized` на `next/image` для уже вручную оптимизированных ассетов (в `/public/features`). Если баг всплывёт на других картинках — тот же обход. Стоит перепроверить при апгрейде Next.js, возможно пофиксят.
