# Russian translation + working language switcher

Date: 2026-09-04
Status: approved, not yet implemented

## Context

The site has always been English-only (per CLAUDE.md's project status: "Контент
(тексты) — финальный, сайт пока только на английском" — multi-language is a
later, separate stage). `LanguageSwitcher.tsx` and `LanguageProvider.tsx`
already exist, but are a UI stub: `current` toggles between the display
strings `"ENG"`/`"RU"`/`"KZ"`/`"العربية"`, and nothing reads that value to
change any rendered text.

A prior project memory (recorded 2026-09-01) already settled the data shape:
translatable fields live as locale maps inline in the same record (e.g.
`title: { en: "...", ru: "..." }` inside each tour object), not as separate
per-language files. This spec builds on that decision and extends it to
static UI copy that doesn't live in a data file.

Scope: translate the entire site to Russian — the one-page site
(`src/app/page.tsx`: Hero, Features, Tours cards, Private tour form, Reviews,
FAQ, Footer, nav) and all six tour detail pages (`/tours/[slug]`, including
the full Timing/Inclusive/Exclusive/Additional information content) — then
wire the switcher so selecting RU actually re-renders the site in Russian.

## Locale type and resolution

```ts
// src/lib/i18n.ts
export type Locale = "en" | "ru" | "kz" | "ar";

export type Localized<T = string> = Partial<Record<Locale, T>> & { en: T };
```

`Localized<T>` is generic so it covers both plain strings (the vast majority
of content) and `ReactNode` (a handful of decorative headlines that mix
inline-styled spans mid-sentence — Hero's `<h1>`, Features' `<h2>`, and the
four Features card labels — where storing per-locale JSX directly is simpler
than inventing a markup mini-language to re-style a translated string).

`LanguageProvider` changes to store a canonical `Locale` code instead of a
display string:

```ts
type LanguageContextValue = { current: Locale; setCurrent: (l: Locale) => void };
```

and persists the choice to `localStorage` (read on mount, written on
change) so a page reload doesn't silently reset to English.

A `useT()` hook wraps `useLanguage()`:

```ts
function useT() {
  const { current } = useLanguage();
  return <T,>(field: Localized<T>): T => field[current] ?? field.en;
}
```

`LanguageSwitcher.tsx` keeps its current dropdown UI, but maps `Locale` codes
to display labels (`{ en: "ENG", ru: "RU", kz: "KZ", ar: "العربية" }`) instead
of using the labels as the state value directly.

KZ and AR stay selectable in the switcher (per the user's explicit call) even
though no translated content exists for them yet — `useT()`'s
`field[current] ?? field.en` fallback means selecting either shows English
text until those languages are translated in a later pass.

## Data layer (`src/data/tours.ts`, `reviews.ts`, `faq.ts`)

Every translatable field becomes `Localized<string>` (or `Localized<string>[]`
for the bullet-list fields):

- `Tour`: `title`, `description`, `badge`, and each entry of `timing`,
  `inclusive`, `exclusive`, `additionalInfo`.
- `Review`: `text`, `reviewDate`. `name` stays a plain string — it's a
  person's name, not copy to translate.
- `FaqEntry`: `question`, `answer`.

Non-text fields (`id`, `price`, `images`, `rating`, `avatar`) are unchanged.
This is the largest volume of work in the spec: 6 tours' worth of
title/description/badge plus every itinerary line across all 6 detail pages,
20 reviews, and 6 FAQ entries.

## Static UI copy (`src/data/copy.ts`, new file)

One new file holds every translatable string that isn't tied to a data
record — organized by section so the whole RU pass can be reviewed in one
place instead of hunting across 15+ component files:

- **Nav** — the menu items (`Main`/`Tours`/`Private tour`/`Reviews`/
  `Education`/`Contacts`) and `Write on WhatsApp`. Currently duplicated
  verbatim between `NavbarContent.tsx` and `MobileMenu.tsx`; this consolidates
  them into one shared source (both components import the same array),
  removing that duplication as a side effect of the refactor.
- **Hero** — location badge ("Kazakhstan, Almaty"), `<h1>`, subtitle,
  "View tours" button.
- **Features** — section `<h2>` and the four card labels.
- **Tours section** — "Your next adventure is waiting – pick one" heading,
  and the card buttons "Book a tour" / "More".
- **Private tour** — section heading, and the form's field placeholders
  ("Full name", "E-mail"), submit states ("Submit a request" / "Sending…"),
  success message ("Thank you!"), and error message. Shared between
  `PrivateTourForm.tsx` and `BookingModal.tsx`, which use the same copy today.
- **Tour detail page** — accordion labels ("Timing", "Inclusive", "Exclusive",
  "Additional information") and the "Book a tour" hero CTA.
- **Reviews / FAQ** — section headings.
- **Footer** — "Social Media & Contacts", "Menu", "Documentation" labels.

Explicitly **not** translated: the `tour: "Private tour"` value sent in the
lead payload to Telegram/Google Sheets (`PrivateTourForm.tsx`) — it's a
backend-facing identifier, not displayed UI copy, and must stay stable
regardless of site language.

## Component changes

Every component that renders one of the fields above calls `useT()` and
wraps the field: `{t(tour.title)}`, `{t(copy.hero.heading)}`, etc. This is a
mechanical, per-component edit — no structural changes to any component
beyond that.

## Out of scope

- SEO `<title>`/`<meta description>` in `src/app/layout.tsx` and each tour's
  `generateMetadata()` — there's no locale-based routing (no `/ru/...`
  segment), so there's only one metadata value regardless of the
  client-side language toggle. Translating metadata would need URL-based
  locale routing, which is a bigger, separate change explicitly deferred by
  CLAUDE.md's roadmap.
- Privacy Policy / Public Offer Agreement pages — currently `href="#"`
  stubs with no real content in either language.
- Image `alt` text.
- Actual KZ and Arabic translations — the switcher supports selecting them
  now (falling back to English), but translating their content is a later
  pass, not part of this spec.

## Build order

1. Architecture: `src/lib/i18n.ts`, `LanguageProvider` refactor,
   `LanguageSwitcher` refactor, empty `copy.ts` scaffold.
2. Translate and fill in RU content: `copy.ts`, then `tours.ts`, `reviews.ts`,
   `faq.ts` (in that order — smallest/most-visible content first).
3. Wire every component to `useT()` and the new field shapes.
4. Verify in-browser: toggle EN↔RU on every section of the home page and on
   all 6 tour detail pages; confirm KZ/AR still fall back to English without
   errors; confirm the choice survives a page reload.
